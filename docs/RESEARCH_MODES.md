## TEIL 1 — Katalog der Spielmodi & Events

**Das strategische Muster (◐ Naavik):** Viele **kurz-getaktete Events stapeln**, damit immer „etwas zu tun" ist
und man **täglich** einloggt. Monetarisierung tragen **Extra-Züge-Kauf** + **Battle-Pass**; Level-Coin-Auszahlung
wird getrimmt, je mehr belohnende Events dazukommen (Royal Match −~30 %).

### A. Kern-Level-Progression (Solo, das Rückgrat)
- **Match-3/Blast-Levels** auf Saga-Map; Normal/Hard/Super-Hard; Fail kostet Leben. Coins → Booster/Extra-Züge/Leben.
- **Episoden** (Candy Crush, ~15 Level/Episode). **Boss-Track** (Royal Kingdom „Dark Kingdom"). **King's Nightmare**
  (Royal Match: Ad-Creative-Levels zwischen Normallevels).

### B. Meta / Renovierung (Solo, das „Warum")
- **Renovierung/Kingdom-Build via Sterne** (1 Stern/Level → Räume/Areale restaurieren): Homescapes/Gardenscapes (Kern),
  Royal Match (bewusst leicht), Royal Kingdom. Candy Crush „Sugar Track" = leichter Sammel-Analog.
- **Renovierungs-Events** (Playrix, 7–10 Tage, Spezial-Tickets) parallel zum Haupt-Meta.

### C. Battle-/Season-Pass (Solo, primäre Live-Ops-Monetarisierung) ✅/◐
- **Royal Pass** (monatlich, 30 Stufen; **Keys** aus Levels, Hard/Super-Hard geben mehr; frei+premium; Reset/Monat;
  Aktivierung: Leben **5→8**, Prestige-Frame, Bonus-Bank). Winter-Pass: 30 Tiers/80 Rewards, **9,99 $**, ~219 $ Wert, +31 % Rev.
- **Home Pass** (7 Tage/15 Stufen), **Golden Ticket** (bis 35 Tage/35 Stufen), **Season of Wonders** (Punkte→Tiers).

### D. Kompetitiv / PvP (Leaderboard, Solo-vs-Andere) — meist mid-game
- **Sky Race** (RM, 5 Spieler, schnellste 15 Level, Top 3) · **Lightning Rush** (RM, 1-h-Sprint, Lightning-Bolts) ·
  **Star Tournament** (Toon Blast, 50 Spieler, ab **Level 25**) · Royal Kingdom: **Champions Arena** (10), **Grand
  Tournament** (50), **Kingdom Duels** (8, Bracket-Elimination), **Island Race** (3 Stages).

### E. Kooperativ / Team (async Guild-Style)
- **Team Treasure** (RM, Schiffsrad-Ziele pooled → Team-Chests) · **Team Tournament** (Toon Blast, Top-5-Teams,
  Preis/50 geteilt) · Royal Kingdom **Team Adventure/Team Clash** (10 Teams, Schilde) · Homescapes Teams (Leben geben/bitten).

### F. „Everyone-finishes"-Jackpot/Step-Events (Solo, nicht-kompetitiv)
- **Piñata Party** (RM, 3 Steps, Candy-Ziele → Piñata) · **Endless Treasure/Lava Quest** (Daily-Jackpot, frei+IAP) ·
  Royal Kingdom **Electro Blitz/Diamond Mine/Magic Carnival** · Homescapes **Map-Exploration** (bis 21 Tage, Energie sammeln).

### G. Streak / „No-Loss"-Boss-Challenges (skill-gated)
- **Bubblegum Hill** (CC, 5 Level auf 1 Leben) · **Super Rainbow Ball** (Homescapes, 10 Level ohne Verlust) ·
  **Triple Win** (Homescapes, 3× Event-Währung bei First-Try) · **Star Chest** (RM/Toon Blast, Sternmeter füllen).

### H. Daily / Login & Collection-Album (Retention)
- **Daily Booster Wheel** (CC, 1 Spin/Tag) · **Royal Collection/Cards + Royal Letters** (RM, Karten aus allen Events →
  Alben) · **Weekly Contest/Area Chests**.

### Must-Have-Modi (de-facto Standard, in fast allen Top-Titeln)
1. Kern-Saga mit Hard/Super-Hard (+Boss) · 2. Sterne-getriebenes Renovier-/Build-Meta · 3. Monats-**Battle-Pass**
(frei+premium) · 4. **PvP-Tournament** (5–50 Spieler) · 5. **async Team-Event** (pooled Chests) · 6. **Jackpot/Step-Event**
(jeder schafft's) · 7. **Daily-Login/Spin** · 8. **Streak/No-Loss-Boss** · 9. **Collection/Album** als Klammer.

## TEIL 2 — Wie sich das Erlebnis über die Zeit verändert (Lifecycle-Evolution)

**Kernprinzip:** Kein „Stapel immer härterer Level", sondern **geschichtete Systeme nach Bloom-Schedule** — der
Puzzle-Kern bleibt stabil, aber Mechaniken/Meta/Social/Monetarisierung **schalten an festen Level-Gates frei und
akkumulieren**. Schwierigkeit als **Rhythmus** (leicht→Spike→Erholung→neue Mechanik), nicht als Rampe. Das Spiel bei
Level 5 ist ein strukturell anderes Produkt als bei Level 500 — auf derselben Engine.

| Phase | Level | Fokus | Was passiert |
|---|---|---|---|
| **1 Onboarding** | 1–30 | Null Reibung, Gewohnheit | 1 Mechanik nach der anderen (RM: Box 1–3, Grass 4–6, dann ~alle 10); Debüt-Level zeigt nur das neue Element; ~95 % Winrate; Booster-Drip; **Feature-Gates**: Star-Chest ~L15, **Teams L20**, Team-Events L23, Butler's Gift L32; Meta-Narrativ ab L1. |
| **2 Mid** | 30–300 | Echte Challenge + erster Spend | **5–10-Level-Schwierigkeitszyklus** (Spike ~L5→Erholung→neue Mechanik); Hindernisse **kombinieren** ab ~L40; **Move-Count** als Hebel; **Near-Loss** (Retention) & **Almost-Win** (Monetarisierung, +5 Züge, eskalierende Preise); **Battle-Pass** als erster paralleler Loop. |
| **3 Late** | 300–1000+ | Meta-Dicke + Harvest | **2–4 gleichzeitige Events** dauernd aktiv; späte Mechanik-Gates (RM Super Light Ball L292); Schwierigkeit nahe Content-Front **gedrosselt**; Monetarisierung wandert von „Level kaufen" zu „Leaderboard kaufen"; **permanente Sammlung** (Karten) ergänzt. |
| **4 Live-Service** | Jahre | Nie endend, Frische per Fabrik-Kadenz | **Endlos** (neue Batch bevor man die Front erreicht; CC 16.000+ Level); **Content-Velocity** (CC ~45 Level/Woche, Toon Blast alle ~12–13 Tage); Events werden länger & komplexer (kurz→72h→Woche→Bracket-Turnier); Saison-Themes rotieren. |

**Bloom-Blueprint (übernehmbar):** *Stage 0 (L1–10):* 1 Mechanik/Zeit, ~95 % Win, Meta-Narrativ ab L1, keine Monetarisierung.
*Stage 1 (L10–30):* Social/Reward-Gerüst **vor** dem Schwierigkeitsanstieg freischalten (Chest L15, Teams L20, Team-Events L23).
*Stage 2 (L30–300):* 5–10-Level-Rhythmus, Move-Count-Hebel, Near-Loss/Almost-Win bewusst designen, Battle-Pass starten.
*Stage 3 (L300+):* 2–4 parallele Events, permanente Sammlung, ein paar Premium-Mechaniken spät, Difficulty an Content-Front plateauen.
*Stage 4:* feste Wochen-/2-Wochen-Kadenz, endlos, Events kurz→lang→Bracket, Saison-Themes; aggressive Monetarisierung erst für späte Kohorten.

## TEIL 3 — Wie man das technisch baut (Multi-Modus + Event-System)

**Vier tragende Patterns:**
1. **Ein geteilter `BoardEngine` + Strategy für Ziele/Win-Conditions** ✅ — Engine kann nur swap/match/clear/cascade;
   jede Regel/Win-Bedingung als `IObjective.Evaluate(BoardState)`. Ein Modus referenziert eine **Liste** `ObjectiveSO`
   (ScoreTarget, CollectColor, ClearBlockers, MovesLimit, TimeLimit) → dieselbe Engine fährt Story/Endless/Timed/Daily
   nur über **Daten**, nicht Code.
2. **Datengetriebene Modus-/Event-Definitionen** ✅ — `GameModeSO`/`EventDefinitionSO` (gespiegelt als Backend-JSON):
   id, coreRuleset, modifiers, objectives[], rewardTable, scoring, segment, **featureFlag**. Neuer Modus/Event = ein
   Asset/eine JSON-Zeile + Flag → **kein Client-Code, kein App-Release**.
3. **ScriptableObject Event-Channels + Pushdown-FSM** ✅ — `EventChannelSO` (OnModeStarted/OnObjectiveCompleted/
   OnRewardGranted) entkoppelt Manager/UI/Audio; `GameFlowStateMachine` (Boot→Hub→ModeLoad→InMode→Pause→Results) als
   Pushdown-Automat (Pause/Overlay pushen/poppen). Additive Szenen + persistente Managers-Szene.
4. **Server-autoritative Live-Ops-Runtime (Metaplay-Modell)** ✅ — Event = **Content** (Dashboard-Config: Dauer/Rewards/
   Params) + **per-Player-State** (Fortschritt). Client liest aktive Events, berechnet **Phase** (Preview→Active→
   EndingSoon→Review→Concluded) aus `serverTimeUtc`, UI rendert generisch nach `template`+Phase; Reward-Grant bei
   Concluded. **Feature-Flags/%-Rollout** für sicheres Dark-Shipping + A/B.

### Kern-Interfaces (Unity, C#)
```csharp
interface IGameState   { void Enter(); void Tick(float dt); void Exit(); }           // FSM
interface IObjective   { ObjectiveProgress Evaluate(BoardState s); void OnBoardEvent(BoardEvent e); }
interface IRuleModifier{ void Apply(BoardConfig cfg); }   // endless=no move cap, timed=timer, +moves …
interface IScoringRule { long Score(MatchEvent m, BoardState s); }
```
### Daten-Schema (Client-SO, gespiegelt als Backend-JSON)
```
GameModeSO          { id, displayName, presentationTemplate, RulesetSO coreRules,
                      IRuleModifier[] modifiers, ObjectiveSO[] objectives, ScoringRuleSO scoring,
                      RewardTableSO rewards, string featureFlag, Segment eligibility }
EventDefinitionSO   { eventId(guid), type{Daily,Timed,Tournament,Season}, GameModeSO mode,
                      presentationTemplate, RewardTable/tiers   // schedule+segment vom SERVER, als Phase geliefert }
RewardTableSO       { entries:[{itemId, qty, weight}], rollType{All|WeightedPick} }
SeasonSO            { seasonId, startUtc, endUtc, BattlePassTrackSO track }
BattlePassTrackSO   { tiers:[{ pointsThreshold, RewardTable free, RewardTable premium }] }
```
### Backend-Endpunkte (FastAPI → Client)
`GET /config/modes` · `GET /liveops/events?playerId` (Schedule+Segment+Flags server-seitig aufgelöst, liefert `phase`
+`playerState`) · `GET /season/current` · `GET /flags?playerId` · `POST /rewards/grant` (autoritativ, Anti-Cheat).
### Manager-Klassen
**LiveOpsService** (fetch/cache, Phase aus `serverTimeUtc`) · **ModeManager** (GameModeSO → BoardEngine + Objectives/
Modifiers/Scoring injizieren) · **GameFlowStateMachine** (Pushdown) · **MetaHubController** (rendert Modi/Events generisch
nach Template, versteckt was `featureFlag=false`) · **RewardService** (Event-/Ranked-Rewards nie client-seitig → `/rewards/grant`).

*Quellen:* Game Programming Patterns (State/FSM/Pushdown), Metaplay LiveOps-Cookbook, Unity (ScriptableObjects: Daten/Logik-
Trennung & Event-Channels; Open-Project-1; Game-Simulation Match-3-Sample), Scott Bilas „Data-Driven Game Object System" (GDC),
ConfigCat/Unity Remote-Config (Feature-Flags), GameGrowthAdvisor (Seasons/Battle-Pass).

- ▶ **Schritt 1 (klein, sichtbar):** Modus-Auswahl-Hub im Prototyp (Story / Endlos / Daily-Seed / Event) — ein
  geteilter Match-3-Kern, Modus nur über Objective+Modifier-Daten. 
- ▶ **Schritt 2:** `IObjective`/`IRuleModifier`/`GameModeSO`-Struktur im Unity-Client; Modi als Daten.
- ▶ **Schritt 3:** Backend `GET /liveops/events` (Phase-Modell) + `RewardTable` + Feature-Flags; ein erstes Event

- ▶ **Bloom-Schedule** aus Teil 2 als Level-/Feature-Gate-Plan in die Level-Daten gießen.
